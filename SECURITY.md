# Security reporting and development status

Do not use this development release for confidential client matters while its security, recovery, licensing and professional validation gates remain open. Local hosting does not itself establish compliance or evidentiary suitability.

Report sensitive vulnerabilities through the repository's private vulnerability reporting channel if enabled, or contact the repository owner privately. Do not publish exploit details, credentials, real evidence, client names or privileged documents in an issue. Public bug reports should use a minimal synthetic reproduction and sanitized diagnostics.

Include the affected commit/version, platform, reproducible steps and expected security boundary. CaseQuarry does not promise a response time or certification. Security fixes must include an appropriate authorization/integrity regression test and preserve original evidence.

See [the threat model](docs/THREAT_MODEL.md), [data handling](docs/DATA_HANDLING.md) and [evidence integrity](docs/EVIDENCE_INTEGRITY.md) for the current boundaries and unresolved deployment requirements.

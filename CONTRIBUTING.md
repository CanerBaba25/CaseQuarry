# Contributing to CaseQuarry

Bug reports, feature requests, documentation improvements and pull requests are welcome at <https://github.com/CanerBaba25/CaseQuarry>.

CaseQuarry uses the Apache License 2.0. Independent forks, modifications, redistribution and commercial use are permitted under its terms. Clearly identify independently maintained versions under the [branding policy](docs/BRAND_POLICY.md).

## Reporting issues

Include the version, environment, reproducible steps, expected behavior and sanitized diagnostics. Use synthetic examples. Never post client evidence, privileged communications, personal records, passwords or tokens. Report sensitive security issues using the instructions in [SECURITY.md](SECURITY.md).

## Proposing changes

Keep pull requests focused. Explain the user-visible behavior, relevant compatibility or migration effects, and checks actually performed. Preserve matter authorization, immutable originals, source provenance, bounded parsing and explicit local-model consent.

Use synthetic material when validating changes. Verification suites and synthetic QA harnesses are maintained locally and excluded from the public source distribution. Public changes should include application source, build configuration and required product documentation. Record actual results; do not claim checks that were not run.

## Contribution rights

Unless you explicitly state otherwise or have a separate agreement, contributions intentionally submitted for inclusion are licensed under Apache 2.0 as described by Section 5. Contributors retain copyright; submitting a pull request does not transfer ownership.

You must have authority to submit your work. Identify third-party code and retain its required notices and compatible terms. Maintainers review submissions before merging; submission does not guarantee acceptance.

Treat contributors respectfully and keep discussions relevant to the project.

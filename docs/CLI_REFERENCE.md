# CLI reference

Install with `uv sync --locked`, then run `uv run casequarry --help`. `cq` is an equivalent entry point. Help is generated by the implementation; commands not present in help are not implemented.

Global flags precede the command: `--server`, `--case`, `--profile`, `--output table|json|csv`, `--limit 1..200`, `--cursor`, `--dry-run`, `--reason`. Common matter/output options also appear after relevant commands. `--yes` is accepted for explicit export confirmation; it never bypasses server permissions or privilege policy.

```sh
uv run casequarry init --local
uv run casequarry health --output json
uv run casequarry auth login --email reviewer@example.org
uv run casequarry auth whoami
uv run casequarry case create --number SYN-001 --title "Synthetic review"
uv run casequarry case list
uv run casequarry ingest plan --case CASE_ID --path .data/synthetic/documents --recursive
uv run casequarry ingest mbox --case CASE_ID --path .data/synthetic/emails.mbox --wait
uv run casequarry ingest files --case CASE_ID --path .data/synthetic/documents --recursive --wait
uv run casequarry search --case CASE_ID --query '"payment approved"' --group-by sender --sort sent_at:asc
uv run casequarry evidence show ITEM_ID --case CASE_ID
uv run casequarry evidence verify ITEM_ID --case CASE_ID
uv run casequarry review decision ITEM_ID --case CASE_ID --value responsive --reason "Reviewed synthetic evidence"
uv run casequarry review tag ITEM_ID --case CASE_ID --tag Financial
uv run casequarry export package --case CASE_ID --path .data/metadata.zip --reason "Synthetic QA" --yes
uv run casequarry audit verify --case CASE_ID
```

Passwords are prompted with hidden input. `auth login --password-stdin` reads one line without echoing it. Bearer sessions are stored in the OS keyring; profile JSON contains server/email only. Tokens are never printed. A secure OS keyring is required for persistent login; there is no plaintext fallback.

Imports are sent in bounded groups of 25 files. `--wait` polls at one-second intervals for up to ten minutes per batch; timeout does not cancel a running server job. MBOX is submitted as one file and parsed as a stream by the worker. Unsupported PST/MSG and other adapters are preserved/reported by the backend and cannot be represented as successful searchable imports.

CSV/JSON exports save a separate `<path>.manifest.json` sidecar and verify the downloaded export hash before writing. Native ZIP requires completed human review for every included item; a blanket confirmation never substitutes for those decisions. Privilege/confidentiality and integrity policies also apply to metadata exports.

Exit codes: 0 success; 2 usage/validation; 3 authentication/authorization; 4 missing or inaccessible item; 5 conflict/blocked transition; 6 partial or continuing operation; 7 subsystem unavailable; 8 integrity failure. Use JSON for automation and inspect both the exit code and reported processing state.

Do not put real evidence or credentials in shell arguments when avoidable, transcripts or public tickets. CLI output is intended for authorized local users and may contain explicitly requested evidence metadata/text.

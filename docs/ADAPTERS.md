# Local ingestion adapters and acquisition

Original bytes remain separate from extraction and OCR artifacts. Every result retains its actual state and error; missing or partial extraction never becomes a successful searchable import automatically. The matter-scoped `/api/v1/cases/{case_id}/imports/adapters` endpoint reports installed readiness and current limits to authorized users.

PDF text extraction runs in a separate process. Pages without native text use local Tesseract through the pypdfium2 renderer when enabled and installed. Images use the same recognition engine. Defaults limit PDFs to 200 pages, each raster to 25 million pixels, recognition to 60 seconds per page, extracted text to four million characters, and document processing to a 180-second traversal budget with an absolute isolated process cutoff after its final allowed page interval. OCR stores per-page methods, text anchors, word counts and mean recognition confidence. Confidence is an engine estimate; every OCR result remains marked `needs-human-verification`.

Set `CASEQUARRY_OCR_ENABLED=false` to disable recognition. Set `CASEQUARRY_OCR_LANGUAGE` to installed Tesseract language data, `CASEQUARRY_TESSERACT_COMMAND` to a trusted local executable if it is outside the standard locations, and adjust the bounded OCR settings in `.env.example` as needed. No recognition service is contacted. Windows detection includes the standard Tesseract installation and `%LOCALAPPDATA%/CaseQuarryTools/tesseract`; Linux normally uses the executable on `PATH`. The Docker API build installs English Tesseract by default; `--build-arg INSTALL_OCR=false` omits it. Docker has not been executed on the current validation host.

MSG extraction runs in a separate process using the documented MS-OXMSG property layout and olefile. It reads email subject, sender/recipients, message identifiers, native UTC FILETIME, plain text or HTML body, and binary file attachments. Bounds include 200 attachments, 64 MiB total attachment bytes, configured property/entry/text limits, and a 60-second isolated timeout. Non-email Outlook objects, encrypted messages, compressed-RTF-only bodies, embedded MSG objects and external/OLE attachments remain unsupported, locked or partial. External attachment references are never followed. String8 properties carry an encoding warning where a Windows-1252 fallback is used. PST/OST extraction and media transcription are unavailable until a real tested local adapter/runtime is configured; their originals remain preserved.

For acquisition, the CLI supports explicit local folders, Maildir and IMAPS. Folder inventory is bounded, refuses symlink roots, skips symlink entries, and records paths relative to the selected scope. Maildir collects only `cur`/`new`, preserving their original relative names; an `.eml` upload label enables MIME parsing while the original provenance path remains unchanged. Import creates a source of the appropriate kind and uses the authenticated public API.

```sh
uv run cq connector folder-inventory --path /authorized/maildir --maildir
uv run cq --dry-run connector folder-import --path /authorized/maildir --maildir --case CASE_ID
uv run cq connector folder-import --path /authorized/maildir --maildir --case CASE_ID --source-label "Authorized mailbox export"
uv run cq connector imap-inventory --host mail.example.org --username reviewer@example.org --mailbox INBOX --maximum 50
uv run cq --dry-run connector imap-fetch --host mail.example.org --username reviewer@example.org --mailbox INBOX --uid 7 --uidvalidity 73 --path /private/acquisition
uv run cq connector imap-fetch --host mail.example.org --username reviewer@example.org --mailbox INBOX --uid 7 --uidvalidity 73 --path /private/acquisition --authorized
uv run cq connector imap-import --path /private/acquisition/acquisition-manifest.json --source-label "Authorized read-only IMAP collection" --case CASE_ID
```

IMAPS validates TLS and hostname; a supplied `--ca-file` adds an explicit trusted certificate chain rather than disabling verification. Credentials are prompted or supplied with `--password-stdin` and never saved. One explicitly named mailbox is opened with `EXAMINE`; originals are fetched with `BODY.PEEK[]`, without changing flags. Inventory exposes UIDs, UIDVALIDITY and sizes; acquisition requires explicit UIDs and the matching UIDVALIDITY. Defaults bound each message to 16 MiB, a collection to 64 MiB and at most 200 UIDs. Oversized protocol literals are refused before allocation. A new private destination holds exact EML bytes and an incremental SHA-256 acquisition manifest; a failure leaves a visibly partial manifest. A completed manifest is verified before API import, which preserves the UID source paths. The ASCII mailbox argument may contain the server's IMAP modified-UTF7 encoding for international names.

Dry runs make no mailbox connection, credential prompt, upload or acquisition writes. The adapter was verified against a real TLS loopback IMAP fixture, including immutable-byte and oversized-literal checks. No external mailbox, OAuth tenant or production account was accessed during validation. Gmail and Microsoft 365 OAuth collection remain unconfigured.

Durable import claims carry an owner nonce and renewable two-minute lease. The worker heartbeats during slow parsing and checks ownership before publication. Parsing holds no SQL write transaction; authorization is checked again after it. Imports yield after a configured record quota (default 25), preserving MBOX offsets and idempotent nested-family checkpoints. One background import slot allows export, redaction/production and optional analysis work to progress while extraction runs. Configured antivirus scanning precedes the document parser; detection quarantines the original and scanner failure prevents extraction.

Explicit retry can reprocess existing partial, failed or unsupported items after an adapter or setting is repaired. It verifies the same original bytes, uses a lease-fenced current-version check, and appends immutable derived-artifact/span versions. Current text and coverage move to the new extraction without duplicating the occurrence; prior artifacts and human reviews remain available. The item warns that changed extraction should be inspected before relying on earlier review. Quarantined originals are not automatically released or reparsed by retry. Retry generations prevent repeated attempts while a quota-limited job resumes.

Unique-original byte quotas are checked under a case writer lock when each original is published, including expanded archive/attachment families and concurrent queued batches. Exact duplicates preserve additional occurrences without charging the same original twice. Reaching quota blocks the new record, marks an incomplete preserved family partial, and records an attributed error and audit event. After an approved limit increase, explicit retry can resume the missing record without retaining a phantom failure count or duplicating its parent. Upload/staging files can exist before publication; this guard is a logical original-byte quota, not a total physical filesystem reservation.

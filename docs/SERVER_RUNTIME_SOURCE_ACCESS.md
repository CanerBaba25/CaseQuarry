# Standalone image runtime notices and source access

The server ZIP includes sharp 0.35.5 and libvips 8.18.7, with the image-library versions recorded in its preserved `runtime-licenses/npm/**/versions.json` files. The upstream package READMEs identify the libraries distributed under LGPLv3 through their LGPLv2 or LGPLv2.1 later-version clauses. Their use remains covered by those licenses. CaseQuarry's Apache-2.0 license does not replace them.

The full LGPLv3 and incorporated GPLv3 texts are included as `runtime-licenses/LGPL-3.0.txt` and `runtime-licenses/GPL-3.0.txt`. Original copyright, license and patent notices recovered from the upstream source distributions are preserved under `runtime-licenses/upstream/`. Package-specific notices and versions are under `runtime-licenses/npm/`.

Matching upstream source is supplied inside the same download in `runtime-sources/`. Its `inventory.json` records each source URL, component version, byte count and SHA-256. Source archives are preserved intact, including upstream notices and build files. The builder refuses changed downloads and native component versions that do not match the reviewed recipe. The archives include the applicable sharp source, libvips and bundled image-library source, Windows MXE and WASM build recipes, and the upstream patches used by the Linux recipe. Additional system libraries and build tools are prerequisites rather than bundled server runtimes.

You may modify these library portions and reverse engineer them for debugging those modifications as provided by the applicable licenses. No CaseQuarry packaging term restricts those permissions. Keep these license texts, notices and source materials when redistributing the runtime.

For a modified library build:

1. Extract the relevant source archives into a separate build directory. The source inventory pins sharp v0.35.5, sharp-libvips v1.3.4, Windows build-win64-mxe v8.18.7, and wasm-vips revision `dca91909178800875b575eb896d1fe4ed0a27931`. This WASM revision is the last recorded commit before upstream's public release job. The timing and matching versions support that inference; the exact SHA resolved by the upstream build was not recorded. The inventory records the evidence and limit; upstream's build script otherwise selects HEAD. The matching WASM GLib and libvips patched source revisions are also supplied. Read their included READMEs, build scripts, version files and platform recipes; they contain the upstream compiler/container flags and dependency configuration.
2. For Linux, use the supplied sharp-libvips `build.sh`, `build/posix.sh` and platform recipe. Source archives and the separate patch files are available locally; the upstream scripts normally fetch those same inputs from the recorded upstream locations. Build your modified libvips and compile sharp against it using [sharp's documented source build](https://sharp.pixelplumbing.com/install/#building-from-source).
3. For Windows, use the supplied build-win64-mxe and matching MXE build sources, followed by sharp-libvips `build/win.sh` and sharp's source build. The distributed libvips DLLs remain separate files beside the sharp Node addon; a compatible rebuilt library/addon can replace those files. [The upstream Windows build project](https://github.com/libvips/build-win64-mxe/tree/v8.18.7) documents its supported toolchain and packaging modes.
4. For WASM, use the supplied wasm-vips sources and patched library revisions with Emscripten 6.0.10, then sharp-libvips `build/wasm.sh` with that pinned revision as its argument and sharp's `build-emscripten` workflow. Sharp's source archive includes its C++ binding source and WASM packaging scripts. Rebuild the combined module and replace the matching `.node.js`/`.node.wasm` runtime files together. [The pinned upstream WASM build source](https://github.com/kleisauke/wasm-vips/tree/dca91909178800875b575eb896d1fe4ed0a27931) documents the build prerequisites.

Stop the server before replacing runtime modules and validate your rebuilt version before restarting. The server manifest checks the original release files; after making your own runtime modifications, keep a manifest for your modified installation. The application source and server controller are supplied under Apache-2.0 in the corresponding CaseQuarry source release, so they can be adapted for a modified runtime. The distributed project wheel contains application source as well.

This records the source and notice materials actually preserved. It does not claim that these upstream native toolchains were rebuilt locally, that a modified binary will be ABI compatible, or that every separate container, externally installed Python dependency, model weight or prerequisite has received legal clearance. The server ZIP does not bundle Python, Node, PostgreSQL or Python dependency wheels; installation obtains the locked Python distributions separately with their own notices.
